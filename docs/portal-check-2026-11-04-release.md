# Релизная проверка Bitrix24 — 4 ноября 2026 года

Проверено через браузер на `b24-aug0be.bitrix24.ru`, в синтетических процессах с пометкой «ТЕСТ». Сервер, вебхук, Bitrix24 REST и покупки не использовались. Это проверка конкретного портала, а не готовность вести реальные договоры или корреспонденцию без настройки под организацию.

## Договоры

[Процесс договоров](https://b24-aug0be.bitrix24.ru/crm/type/1040/list/category/0/) получил обязательные поля `Номер договора` (строка), `Дата договора` (дата), `Контрагент` (строка), `Предмет договора` (строка) и `Статус договора` (список). В списке статусов: `Черновик`, `На согласовании`, `Подписан`, `Завершён`, `Расторгнут`. Необязательные поля: `Ссылка на проект`, `Сумма договора`, `Дата окончания`, `Файл договора`. Системные `ID` и `Доступно для всех` показаны в карточке.

В [тестовой карточке ID 1](https://b24-aug0be.bitrix24.ru/crm/type/1040/details/1/) сохранены номер `ТЕСТ-001`, дата `04.11.2026`, синтетический контрагент, предмет, статус `Черновик` и ссылка на [тестовый проект](https://b24-aug0be.bitrix24.ru/workgroups/group/1/). Карточка после сохранения показала `Доступно для всех: Нет`. Номер договора введён вручную: автоматического правила для него нет.

## Корреспонденция

[Процесс корреспонденции](https://b24-aug0be.bitrix24.ru/crm/type/1046/list/category/0/) получил обязательные поля `Направление` (`Входящая`/`Исходящая`), `Тема` и `Дата документа`. Необязательные поля: `Отправитель`, `Получатель`, `Номер документа` (номер на самом документе), `Файл документа`, `Ссылка на проект`, `Ссылка на договор` и `Регистрационный номер`. В [тестовой входящей карточке ID 1](https://b24-aug0be.bitrix24.ru/crm/type/1046/details/1/) сохранена кликабельная ссылка на тестовый договор. Поле `Связанный договор` типа «Привязка к элементам CRM» не нашло этот договор в выборе; оно скрыто из карточки и списка. Настройка отображения связанных элементов включена, но сама штатная связь между процессами не подтверждена.

Для процесса включены стадии и роботы. В [настройках роботов](https://b24-aug0be.bitrix24.ru/crm/type/1046/automation/17/) два робота `Изменить элемент` работают на стадии `Начало` сразу после создания. Каждый проверяет соответствующее направление **и** пустой `Регистрационный номер`; изменяет только этот номер. Для входящих задано `ВХ-{{ID элемента CRM}}`, для исходящих — `ИСХ-{{ID элемента CRM}}`. После сохранения роботы остались в настройке при повторном открытии страницы.

| Запись | Как получен номер | Проверенный номер |
| --- | --- | --- |
| [Входящая ID 1](https://b24-aug0be.bitrix24.ru/crm/type/1046/details/1/) | Ранняя тестовая запись, позже приведена к формату вручную | `ВХ-T416_1` |
| [Исходящая ID 3](https://b24-aug0be.bitrix24.ru/crm/type/1046/details/3/) | Ранняя тестовая запись, позже приведена к формату вручную | `ИСХ-T416_3` |
| [Входящая ID 5](https://b24-aug0be.bitrix24.ru/crm/type/1046/details/5/) | Присвоил робот после создания | `ВХ-T416_5` |
| [Исходящая ID 7](https://b24-aug0be.bitrix24.ru/crm/type/1046/details/7/) | Присвоил робот после создания | `ИСХ-T416_7` |

Номера ID 5 и 7 подтвердились после повторного открытия карточек. У ID 7 затем изменена тема; номер остался `ИСХ-T416_7`. `{{ID элемента CRM}}` на этом портале возвращает составное значение `T416_<ID>`. Пропуски числовых ID наблюдались. Роботы используют присвоенный Bitrix24 ID, поэтому агент не вычисляет следующий номер. Параллельное создание большого числа записей и защита от ручной правки номера не испытывались; уникальное ограничение базы данных не проверялось. В проверенных карточках значение `Доступно для всех` было `Нет`.

## Граница релиза

Проверка отдельного нового чата после установки 1.0.0, других порталов и реальных документов не входит в эту проверку.
