# Как пользоваться локальным агентом Bitrix24

Плагин `bitrix24-local-agent` помогает работать с Bitrix24 из локального чата настольного ChatGPT/Codex. Он читает и меняет данные через браузерный интерфейс портала. Свой сервер, Bitrix24 REST и вебхук не нужны. Компьютер должен быть включён, а ChatGPT и Bitrix24 — доступны через интернет. Сообщение с телефона само по себе не запускает работу на выключенном ПК.

## Быстрый старт на этом компьютере

1. Открой настольный ChatGPT/Codex и выбери локальный режим Work. Создай **новый чат** после установки или обновления плагина.
2. Убедись, что `bitrix24-local-agent` установлен и включён. Если в чате требуется выбор плагина, выбери его через меню плагинов или через `@`.
3. Открой нужный портал Bitrix24 во встроенном браузере приложения и войди в свой аккаунт. Пароль и код входа вводи только на странице Bitrix24. Если используешь обычный Chrome, для управления его вкладками нужен установленный плагин Chrome и его расширение; для встроенного браузера нужен Browser.
4. Напиши поручение с адресом портала, объектом и конкретным действием. Агент должен проверить портал и существующую запись, выполнить действие через интерфейс и дать ссылку или ID результата.

Пример первого поручения без изменения данных:

> Используй локальный агент Bitrix24. На портале `b24-aug0be.bitrix24.ru` найди тестовый проект и покажи его задачи. Ничего не меняй.

Примеры поручений с записью:

> На портале `b24-aug0be.bitrix24.ru` создай тестовую задачу в проекте «…» с названием «…» и описанием «…». Срок не ставь. После сохранения проверь проект, исполнителя и дай ссылку.

> В тестовом процессе корреспонденции создай входящее письмо: тема «…», дата документа «…», отправитель «…». Свяжи его ссылкой с проектом «…». После сохранения открой карточку ещё раз и сообщи номер, который присвоил Bitrix24.

Для рабочего портала сначала попроси агента **прочитать** доступные процессы и поля. Тестовые процессы `b24-aug0be.bitrix24.ru` не задают схему для другого портала. Если агент не может однозначно выбрать проект, запись или поле, уточни цель в чате.

## Установка на другом Windows-ПК

Нужны настольный ChatGPT/Codex, Git, PowerShell и доступ к [приватному репозиторию](https://github.com/lowen-tokyo/bitrix24-local-agent). В PowerShell выполни:

```powershell
git clone https://github.com/lowen-tokyo/bitrix24-local-agent.git
Set-Location .\bitrix24-local-agent
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-local.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-auto-updates.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\doctor.ps1
```

После установки создай новый локальный чат. `ExecutionPolicy Bypass` действует только для запущенного процесса PowerShell. Скрипт установки добавляет локальный каталог плагинов `bitrix24-local` и устанавливает `bitrix24-local-agent`; он не устанавливает сам ChatGPT/Codex, Git или браузерный плагин.

В рабочем результате `doctor.ps1` версии `SourceVersion` и `InstalledVersion` совпадают, `PluginEnabled` и `OriginConfigured` равны `True`, задача `UpdateTaskState` существует и не отключена. Скрипт не проверяет вход в Bitrix24 и способность конкретного чата управлять браузером.

## Обновление

Проверка обновлений запускается при входе в Windows и ежедневно в 10:00 по местному времени ПК. Посмотреть её журнал:

```powershell
Get-Content -LiteralPath "$env:LOCALAPPDATA\Bitrix24LocalAgent\updates.log" -Tail 30
```

Запустить проверку вручную из папки репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-local.ps1
```

Обновление берётся из Git `origin` только для чистой текущей ветки и только когда изменения можно применить без слияния. При локальных изменениях или расхождении истории скрипт пропустит обновление и запишет причину в журнал. После успешного обновления открой новый чат, чтобы загрузить новую версию плагина. Документация в репозитории обновляется вместе с исходниками; установленная версия плагина меняется только при изменении его пакета.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Плагин не виден | Запусти `doctor.ps1`; проверь, что установка завершилась без ошибки, затем открой новый локальный чат. |
| Агент не видит Bitrix24 | Проверь адрес портала, вход в аккаунт и доступность вкладки через Browser или Chrome. Встроенный Browser и обычный Chrome требуют разных средств управления. |
| Нет доступа к проекту или полю | Проверь права своего аккаунта в Bitrix24. Плагин не расширяет их. |
| У тестового письма пустой регистрационный номер | Открой сохранённую карточку повторно и проверь роботов процесса. Не вычисляй следующий номер вручную и не создавай дубль письма. |
| Автообновление пропущено | Прочитай `updates.log`, затем проверь `git status --branch --short` в папке репозитория. Скрипт сохраняет локальные изменения. |

Не отправляй в чат пароль, одноразовый код или URL вебхука. Для тестов используй записи с пометкой «ТЕСТ» и вымышленные данные. Агент может работать только с теми объектами и правами, которые доступны твоему аккаунту в интерфейсе Bitrix24.

## Что проверено

На одном тестовом портале проверены проект, задача, CRM-сделка, поля двух смарт-процессов и присвоение номеров новым входящему и исходящему письмам штатными роботами Bitrix24. Подробности и ограничения — в [отчёте о проверке 1.0.0](portal-check-2026-11-04-release.md). Другие порталы, реальные документы и рабочие права доступа требуют отдельной проверки.

Официальные инструкции OpenAI: [локальные плагины](https://developers.openai.com/plugins/build/plugins), [управление встроенным браузером и Chrome](https://developers.openai.com/training/walkthroughs/using-your-computer-and-browser).
