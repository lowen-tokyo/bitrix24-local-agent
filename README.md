# Локальный агент для Bitrix24

Этот проект — локальный агент для работы с любым порталом Bitrix24 и любыми доступными пользователю проектами. Он устанавливается как плагин настольного ChatGPT/Codex и выполняет поручения через интерфейс браузера: находит записи, читает их, создаёт и изменяет по конкретному запросу. Отдельный сервер, REST API и вебхук для этого варианта не нужны.

Агент работает, когда компьютер включён, в настольном приложении открыт локальный чат и пользователь вошёл в нужный портал. ChatGPT и сам Bitrix24 используют интернет; агент не обращается к сторонним сайтам или API для работы с данными портала. На любом портале он сначала проверяет, где находится нужный объект, чтобы не путать проекты, задачи и элементы CRM.

## Установка

Из корня проекта запустите:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-local.ps1
```

Затем откройте новый локальный чат в настольном ChatGPT/Codex с плагином `bitrix24-local-agent`. Примеры поручений: «Найди проект по названию и покажи задачи», «Создай задачу в проекте X с таким описанием», «Найди договор по номеру». Для записи агент проверит существующие данные, выполнит действие и сообщит ссылку или ID результата.

Для быстрой локальной диагностики запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\doctor.ps1`. Скрипт проверяет установленную версию плагина и задачу обновления Windows; он не проверяет вход в конкретный портал. Параметр `ExecutionPolicy Bypass` действует только для запущенного процесса PowerShell и нужен на ПК, где запуск локальных скриптов по умолчанию запрещён.

Исходники хранятся в [приватном репозитории](https://github.com/lowen-tokyo/bitrix24-local-agent). После клонирования на другой компьютер включите проверку обновлений командой `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-auto-updates.ps1`. На текущем компьютере она уже включена.

Плагин использует средства управления браузером, доступные в настольном приложении. Если их нет в установленной версии, навык сам по себе не сможет управлять порталом. Обычный Custom GPT в браузере не запускает локальную программу на ПК.

## Состояние

Версия 0.5.3 устанавливает универсальный навык. 3 ноября 2026 года на портале `b24-aug0be.bitrix24.ru` через интерфейс созданы [тестовый проект](https://b24-aug0be.bitrix24.ru/workgroups/group/1/), [задача № 1](https://b24-aug0be.bitrix24.ru/company/personal/user/1/tasks/task/view/1/) и [тестовая CRM-сделка](https://b24-aug0be.bitrix24.ru/crm/deal/details/1/). Проверены поиск, чтение и изменение записей, а также переходы статуса задачи. Подробности — в [отчёте за 3 ноября](docs/portal-check-2026-11-03.md).

4 ноября дополнительно созданы два смарт-процесса типа «Список»: [тестовые договоры](https://b24-aug0be.bitrix24.ru/crm/type/1040/list/category/0/) и [тестовая корреспонденция](https://b24-aug0be.bitrix24.ru/crm/type/1046/list/category/0/). В каждом создана тестовая запись; запись корреспонденции изменена, новое название подтвердилось после перезагрузки. [Отчёт за 4 ноября](docs/portal-check-2026-11-04.md) содержит ссылки на записи и точные границы проверки. Эти процессы пока содержат только название элемента: реальные реквизиты договора, направление и дату письма, связи с проектами и автоматическую нумерацию нужно настраивать по согласованной схеме. Другие порталы пока не проверялись. В этом портале REST API и вебхуки были закрыты подпиской; пробный период не включался.

Проверку обновлений выполняет `scripts/update-local.ps1`: она получает новую версию из Git `origin`, обновляет только чистую ветку с прямым продолжением истории и переустанавливает плагин. `scripts/enable-auto-updates.ps1` создаёт проверку при входе в Windows и ежедневно; результаты пишет в `%LOCALAPPDATA%\Bitrix24LocalAgent\updates.log`. Без удалённого `origin` проверка просто пропускается.

3 ноября 2026 года обновление проверено на этом ПК двумя способами: ручной запуск перевёл чистую папку с версии 0.5.0 на 0.5.1, а задача планировщика — с 0.5.1 на 0.5.2. После второго запуска плагин был включён в версии 0.5.2, результат задачи Windows — `0`. Следующий ежедневный запуск назначен на 4 ноября, 10:00.
